Features

One command takes a project from source to a live URL — with immutable deploy URLs, a mutable alias for production, instant rollback, previews, and a terminal UI that is also fully scriptable.

The core loop

deploy up (or bare deploy) does the whole job in one step:

  1. Detect the build. Reads package.json, finds the "build" script, and runs it with the package manager detected from your lockfile — npm, pnpm, yarn, or bun. No build script? It skips straight to the output folder.
  2. Find the output. Looks in dist/, build/, out/, or public/ — or treats the project root as static if it already contains an index.html. Override any of it with --dir <path> or .deployrc.json → {"outDir": "…"}.
  3. Upload. Ships the folder to whichever provider you chose, using that host's documented upload contract (see Providers).
  4. Print the URL. Both the production alias and the immutable per-deploy URL.
Every file is uploaded once, unchanged files between deploys are deduped, and uploads are idempotent — a retried upload never creates duplicates. Network failures and 5xx/429 responses are retried automatically with exponential backoff.

URL model & aliases

Every deploy gets a stable address; production is a pointer that can move:

URLMeaning
…/latest/the alias that always points at the current production deploy
…/preview-<branch>/preview alias, created by deploy preview
…/<deployId>/immutable — that exact upload, forever

Aliases are pointers in the control plane's registry.json — flipping one is the rollback operation, so no bytes ever move.

Command reference

deploy

The interactive menu in a terminal; otherwise behaves as up.

deploy up

Build + upload + print the live URL. The day-to-day command.

deploy preview

Deploy the current branch to its own preview URL — production untouched.

deploy rollback <id>

Re-point the production alias at a previous deploy. Instant locally.

deploy list

Deploy history for the project; ★ marks the current production.

deploy status

Project, default provider, per-provider login state, last deploy.

deploy diff

Added/changed/removed files vs the latest local deploy.

deploy watch

Deploy once, then rebuild + redeploy on every file change. Ctrl+C stops it.

deploy login

Save credentials — interactive with a masked prompt, or with flags.

deploy server

Start the bundled local control plane (--port, --storage, --token).

deploy doctor

Health report: config, login state, and a live connectivity probe per provider.

deploy completion <shell>

bash / zsh / fish tab completions.

deploy token

Print the dev server's write token.

FlagEffect

--no-buildskip the build step entirely (handy in CI after an earlier job built)
--provider <name>local | netlify | vercel | cloudflare | s3

--timeout <s>bound host polling (default 60s)

--verbosestack traces for debugging

Interactive terminal UI

Bare deploy in a terminal shows a menu — Deploy now, Preview deploy, Login, List deploys, Rollback, Status, Watch, Diff, Quit — navigated with arrow keys. deploy login and deploy rollback use the same pickers, and token entry is masked: you see ********, never the value. All of it is ~150 lines of readline — zero dependencies.

Prompts only appear when stdout is a terminal. In scripts and CI they degrade to numbered input (or fail fast), so a pipeline can never hang on a question. Force the interactive path with DEPLOY_FORCE_TTY=1.

CI-safe by design

  • --json keeps stdout pure JSON — parse it with jq .url or any JSON tool.
  • Tokens come from env vars (NETLIFY_AUTH_TOKEN, VERCEL_TOKEN, CLOUDFLARE_API_TOKEN, AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY) or the config file — never prompts.
  • DEPLOY_CONFIG_DIR moves the credential file out of the workspace (e.g. $RUNNER_TEMP).
  • The bundled control plane means preview deploys need no external accounts.

Reliability

  • Retries with backoff on network errors and 5xx/429 for every provider.
  • Idempotent uploads — retrying never duplicates a deploy or an object.
  • Pre-flight checks warn before you hit host caps; --force overrides.
  • Host-aware waits — Netlify polls to ready, Vercel to READY, Cloudflare to success, so the URL you get back actually serves.
  • deploy doctor verifies config, login state, and live host connectivity — run it before blaming the deploy.

Security

  • Credentials live in ~/.deploy-cli/config.json (mode 0600), never in the repo.
  • The control plane's public side is read-only; writes require the bearer token.
  • Provider tokens are stored per provider and only sent to that provider's API.
  • Environment-var overrides (including *_API_BASE endpoints) let you test against sandboxes or proxies without touching production.
