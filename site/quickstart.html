Quickstart

Ship your first site to the bundled local control plane in about two minutes — no cloud accounts required. Then push the same commands at Netlify, Vercel, Cloudflare Pages, or S3.

1. Install

npm install -g @mayan1124/deploy-cli

Verify:

deploy --version
deploy --help
Requirements: Node.js ≥ 18 (the CLI uses built-in fetch — no other dependencies). In a checkout you can also run node cli.js up, or npm link to get a global deploy command pointing at your repo. Update with npm update -g @mayan1124/deploy-cli.

2. Start the local control plane

The control plane stores deploys and serves them on :8787:

deploy server
# deploy server on http://localhost:8787
#   storage: ./.deploy-storage
#   token:   dev-token

Leave it running in its own terminal. Port taken? deploy server --port 9000, then deploy login --server http://localhost:9000.

3. Login

deploy login
# ✔ Credentials saved for http://localhost:8787

In a terminal you'll be asked which provider and (for host providers) your token — typed into a masked prompt so it never shows on screen. Tokens are stored in ~/.deploy-cli/config.json (mode 0600). Override the location with DEPLOY_CONFIG_DIR, useful in CI and sandboxes. Skip the prompts anytime with flags: deploy login --provider netlify --token <PAT>.

4. Deploy

From your project root (any project with a build script, a public/ folder, or an index.html):

deploy

In a terminal you get the interactive menu — pick Deploy now. Or skip the menu with deploy up:

deploy up

The CLI will:

  1. Detect your build — reads package.json, finds "build", and runs it with the package manager detected from lockfiles (npm, pnpm, yarn, or bun).
  2. Find the output folder — dist/, build/, out/, public/, or the project root if it's already static.
  3. Upload it and print your URLs:
✔ Deployed 20260815-091200-ab12
  URL:    http://localhost:8787/my-app/latest/
  Deploy: http://localhost:8787/my-app/20260815-091200-ab12/
URLMeaning
…/latest/the alias that always points at the current deploy
…/20260815-…/the immutable URL for this exact deploy — never changes

5. Open it

deploy up --open      # opens the URL in your browser

What's next

  • Iterate: deploy watch rebuilds and redeploys on every file change.
  • Preview a branch: deploy preview — production is untouched.
  • Roll back: deploy rollback <deployId> — instant alias re-point.
  • Compare: deploy diff shows what changed vs the last local deploy.
  • Deploy to a real host: see Providers.

Deploying React apps

React projects are auto-detected: the CLI runs your build script and finds the output folder.

Vite

vite build outputs to dist/ — detected automatically:

cd my-vite-app
deploy up                        # local control plane
deploy up --provider netlify --site my-site
deploy up --provider vercel

Create React App

react-scripts build outputs to build/ — also auto-detected:

cd my-cra-app
deploy up

Custom output folders

deploy up --dir out
# or permanently:
echo '{ "outDir": "out" }' > .deployrc.json

Build-time environment variables

VITE_* / REACT_APP_* variables are baked in during the build, which runs on your machine, so they just work:

VITE_API_URL=https://api.example.com deploy up

Client-side routing (React Router)

With BrowserRouter, deep links (/about) are resolved by the server on a static host — and 404 unless you add a fallback to index.html:

  • Netlify — add public/_redirects: 
    /* /index.html 200
  • Vercel — add vercel.json: 
    { "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
  • Local control plane — SPA fallback built in: deep links serve index.html automatically (assets still 404 correctly).
  • Cloudflare Pages / S3 — use each host's equivalent SPA routing config.

Preview a branch

git checkout -b feat/landing
deploy preview --provider netlify
# URL on the branch preview — production untouched
One caveat for React + API: the CLI ships static output. Point your API calls at a separate host, or pre-build any functions into the output folder — this CLI uploads built output, so host functions must already be built to be included.
