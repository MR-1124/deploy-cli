Gallery

Real projects shipped with deploy-cli. Each entry was deployed with the exact command shown, is live right now, and was uploaded with one of the CLI's provider integrations.

Live deployments

deploy-cli website

This landing page and its docs — dogfooding: the CLI ships its own website. Served from a plain S3 object-store URL, no website hosting configured.

s3 ● live

deploy up --provider s3 --project deploy-cli --dir site --no-build

sample-site

The repo's example static site — the same one the quickstart deploys. Two files, uploaded with one command.

s3 ● live

deploy up --provider s3 --project sample-site --dir examples/sample-site --no-build

Verified by the release pipeline

Beyond the persistent deployments above, every release runs a real-account smoke test — the CLI deploys a site to all four hosts, verifies the served content, exercises rollback, and then the workflow cleans the artifacts up:

ProviderWhat the smoke provesStatus
Netlifydigest deploy → ready → content check → restore rollback✔ passing
VercelSHA1 upload → READY wait → content check → two-deploy rollback✔ passing
Cloudflare Pagesupload-token direct upload → success → content check✔ passing
S3SigV4 upload → object content check✔ passing

See the latest run on the release pipeline, or read how it works in the smoke-test guide.

Deploy your own

Any of these entries took one command. Yours will too:

cd my-project
deploy up --provider s3 --project my-project      # or netlify / vercel / cloudflare

Start with the quickstart, or compare the providers.
